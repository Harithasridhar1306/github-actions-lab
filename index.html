How to use this lab

The intended loop is simple: learn → build → break → diagnose → fix → explain.

📚 1. Learn the concept

  • Read the short explanation.
  • See the YAML pattern.
  • Check “What actually happens?” for the execution model.

🛠️ 2. Build it yourself

  • Create a tiny workflow in a test repository.
  • Run it with workflow_dispatch.
  • Inspect the run, jobs, steps and logs.

💥 3. Break it on purpose

  • Change a job dependency.
  • Break an expression or permission.
  • Watch the failure instead of immediately looking at the answer.

🔎 4. Diagnose & explain

  • Use the challenge hints.
  • Fix the workflow.
  • Explain why the fix works in your own words.
Rule of the lab: don't just copy the YAML. If you can predict what GitHub will do before you press “Run workflow”, you actually understand it.

🧪 Challenge: fix the dependency

A small failure with a real CI/CD concept behind it.

INTERMEDIATE · JOBS
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: npm run build

  deploy:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - run: ./deploy.sh

What is wrong?

What should it become?

deploy:
  needs: build

needs creates a dependency on another job ID. The deploy job therefore waits for build to complete successfully.
