Execution & Dependencies

Understand Actions as a dependency graph: what runs in parallel, what waits, and how data crosses jobs.

Mental model

independent jobs can fan out; needs creates edges

Learn the execution model first. Syntax comes second.

Today's build

Build build/test in parallel, make deploy wait for both, then break test and trace the skipped deploy.

01 · Understand

Jobs form a graph

build ──────┐ ├──→ deploy test ──────┘

Without needs, independent jobs can run concurrently. needs creates an explicit dependency and changes execution order.

02 · Build it

Parallel build and test, then deploy

jobs:
  build:
    runs-on: ubuntu-latest
    steps: [{run: echo build}]
  test:
    runs-on: ubuntu-latest
    steps: [{run: echo test}]
  deploy:
    needs: [build, test]
    runs-on: ubuntu-latest
    steps: [{run: echo deploy}]

Build and test can start independently. Deploy waits for both to succeed.

03 · Pass data

Step output → job output → needs

jobs:
  build:
    runs-on: ubuntu-latest
    outputs:
      image: ${{ steps.meta.outputs.image }}
    steps:
      - id: meta
        run: echo "image=myapp:123" >> "$GITHUB_OUTPUT"
  deploy:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - run: echo "Deploying ${{ needs.build.outputs.image }}"

Learn this chain: a step creates an output, the job exposes it, and a dependent job reads it through needs.

04 · Break it

Why did deploy get skipped?

- run: exit 1

Make the test job fail. Deploy is skipped because its dependency did not complete successfully.

When a job is skipped, trace its needs chain before assuming the skipped job is broken.
05 · Fix it

Status functions are deliberate escape hatches

A reporting or cleanup job may intentionally use always() so it can run after failures. Use this consciously because it changes normal dependency behavior.

Final challenge

Build and test are independent; deploy must wait for both. What expresses that?

Don't look it up yet. Explain what you would inspect and why.

Reveal the answer
needs: [build, test]. needs creates the dependency edges.
