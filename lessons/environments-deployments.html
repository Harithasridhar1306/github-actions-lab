Environments & Deployments

Approvals, environment protection, deployment flow and release controls.

Mental model

build → environment → approval → deploy

Learn the execution model first. Syntax comes second.

Today's build

Create staging and production targets and identify exactly where protection rules affect the run.

① Understand

What is GitHub responsible for? What is executed by the runner? What information crosses the boundary? Write the flow in plain English before touching YAML.

② See it

Use a tiny workflow and inspect the run summary, job graph, logs, contexts and generated outputs. Don't just read the YAML — observe what it produces.

③ Build it

Create staging and production targets and identify exactly where protection rules affect the run.

④ Break it

Change exactly one assumption on purpose. Make a trigger not match, a dependency fail, an output disappear, a permission become too restrictive, or an environment gate intervene.

⑤ Fix it

Form one hypothesis → gather evidence → make one change → rerun → explain the root cause. The explanation is part of the exercise.

Mini workflow

name: learning-lab

on:
  workflow_dispatch:

jobs:
  learn:
    runs-on: ubuntu-latest
    steps:
      - name: Inspect the runner
        run: |
          echo "OS=$RUNNER_OS"
          echo "Architecture=$RUNNER_ARCH"
          pwd
          echo "Hello from the runner"
