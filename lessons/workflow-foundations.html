Workflow Foundations

Stop reading Actions YAML as configuration. Learn to see the execution system underneath it.

Mental model

event → workflow → run → runner → job → step

Learn the execution model first. Syntax comes second.

Today's build

Build a workflow, inspect the run, then break the trigger and diagnose why nothing starts.

01 · Understand

What happens after git push origin main?

push event → matching workflow → workflow run → job → runner → steps

GitHub first evaluates whether the event matches the workflow's on configuration. A matching workflow creates a run. Jobs are then scheduled onto runners, and the runner executes the steps.

02 · See it

Read a real workflow

name: Build App

on:
  push:
    branches: [main]
  workflow_dispatch:

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: echo "Building $GITHUB_SHA"

on = when. jobs = execution units. runs-on = runner environment. steps = commands/actions executed in order.

03 · Build it

Inspect the runner instead of guessing

jobs:
  inspect:
    runs-on: ubuntu-latest
    steps:
      - run: |
          echo "OS=$RUNNER_OS"
          echo "ARCH=$RUNNER_ARCH"
          pwd
          ls -la

Run it manually, open the job, and inspect every log line. Your goal is to connect the YAML to the actual machine that executed it.

04 · Break it

Make the workflow silently not match

on:
  push:
    branches: [develop]

Now push to main. The YAML is valid, but the event does not match.

Debug: If a workflow never starts, inspect the event, branch/path filters and workflow location before touching the job.
05 · Fix it

Works locally, fails in Actions

Compare OS, shell, PATH, working directory, permissions and installed tools. Add temporary diagnostics such as which node, pwd or env rather than changing five things at once.

Final challenge

You push to main and nothing runs. What do you inspect first?

Don't look it up yet. Explain what you would inspect and why.

Reveal the answer
The on trigger and its branch/path filters. A valid workflow still won't execute for an event it doesn't match.
